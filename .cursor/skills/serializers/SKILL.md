# Serializers

## Overview

Serializers transform data from our internal types (short, simple names) to the format expected by external APIs (verbose names). They handle field name mapping, data transformation, and type conversion for outgoing requests.

**Full documentation**: See `src/lib/TRANSFORMATIONS.md` for complete field mappings and examples.

**Where to use**: Only in **API routes** when the route sends data to an external API. Actions and hooks do not use serializers (they send internal format to the internal API).

## Location

All serializers go in `src/lib/serializers/`. Use kebab-case for file names. Export from `src/lib/serializers/index.ts`.

```text
src/lib/serializers/
├── user-serializer.ts
├── index.ts
└── README.md
```

## Field Mappings (User Example)

| Internal (short) | External API (verbose) |
| ---------------- | ---------------------- |
| `id` | `_id` |
| `name` | `fullName` |
| `email` | `emailAddress` |
| `role` | `userRole` |

## Structure

```tsx
// src/lib/serializers/user-serializer.ts
import type { User, CreateUserBody, UpdateUserBody } from "@/types/user";

const serializeRole = (role: User["role"]): string => role.toLowerCase();

export const serializeUser = (user: User): Record<string, unknown> => {
  return {
    _id: user.id,
    fullName: user.name,
    emailAddress: user.email,
    userRole: serializeRole(user.role),
  };
};

export const serializeCreateUser = (data: CreateUserBody): Record<string, unknown> => {
  return {
    fullName: data.name,
    emailAddress: data.email,
    userRole: serializeRole(data.role),
    // ... (excludes id since it's generated by API)
  };
};

export const serializeUpdateUser = (data: UpdateUserBody): Record<string, unknown> => {
  const serialized: Record<string, unknown> = {};
  if (data.name !== undefined) serialized.fullName = data.name;
  if (data.email !== undefined) serialized.emailAddress = data.email;
  if (data.role !== undefined) serialized.userRole = serializeRole(data.role);
  // ... only serialize fields that are present
  return serialized;
};
```

## Usage in API Routes

Use `externalClient` from `@/lib/api/external-client`. Request body is already internal format (`CreateUserBody` / `UpdateUserBody`). Serialize before sending; normalize the external response when reading.

```tsx
// src/pages/api/users.ts
import { serializeCreateUser } from "@/lib/serializers";
import { normalizeUser } from "@/lib/normalizers";
import { externalClient } from "@/lib/api/external-client";
import type { CreateUserBody } from "@/types/user";
import type { ExternalUserResponse } from "@/types/external-user";

// POST: body is CreateUserBody (internal); external returns { data: ExternalUser }
const serializedData = serializeCreateUser(body);
const response = await externalClient.post<ExternalUserResponse>("users", serializedData);
const user = response.data?.data ? normalizeUser(response.data.data) : null;
return res.status(201).json({ message: HTTP_RESPONSE_MESSAGE.SUCCESS, data: { user }, status: 201 });
```

## Export Pattern

```tsx
// src/lib/serializers/index.ts

```

```tsx
import { serializeUser } from "@/lib/serializers";
```

## Important Notes

- **Location**: `src/lib/serializers/` (not `src/serializers/`)
- **File naming**: Use kebab-case (e.g., `user-serializer.ts`)
- **One-way transformation** - Serializers only convert internal → external format
- **Use normalizers for the opposite** - External → internal (see normalizers skill)
- **See `src/lib/TRANSFORMATIONS.md`** for complete field mappings
- **Keep serializers pure** - No side effects, just data transformation
- **Value transformations**: Map internal types to external format (e.g. role union → string)
- **Field transformations**: Short names → verbose names
- **Internal types**: Define in `@/types/{resource}` (e.g. `User`, `CreateUserBody`, `UpdateUserBody`)
